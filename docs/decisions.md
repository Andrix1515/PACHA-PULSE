# Decisiones

## 2026-11-14 — Inicio y alcance

- **D001 — Fase 0 primero.** La carpeta estaba vacía. Se prepara documentación y se verifica el entorno antes del código funcional; no se salta a otra fase sin indicación del usuario.
- **D002 — Raíz de trabajo.** Se utiliza `Farm_Project` directamente, sin crear otra carpeta `agroshift/`. Las instrucciones vigentes se leyeron de `../AGENTS.md`; la guía complementa el contexto. Se evita duplicar esos documentos y generar versiones divergentes.
- **D003 — Python explícito.** Se selecciona Python 3.12.10, disponible y dentro del mínimo requerido. `py` tiene 3.14 como predeterminado, por lo que el futuro entorno se creará con `py -3.12 -m venv .venv` desde `backend/`. No se ha creado todavía.
- **D004 — Stack conservado.** React/Vite/TypeScript, Tailwind, Leaflet, Recharts y FastAPI/Pydantic/HTTPX/SQLite. Las versiones de paquetes se decidirán al verificar documentación y compatibilidad en Fase 1; no se afirma que Node 22.15.0 admita cualquier versión futura de Vite.
- **D005 — Ciencia separada.** Observaciones, indicadores derivados, predicciones, escenarios e interpretaciones tendrán categorías explícitas. La comparación no dependerá de ML ni de NDVI como medida de rendimiento.
- **D006 — Dependencias incrementales.** No instalar paquetes ni crear entornos en Fase 0. Sin Docker, PostgreSQL/PostGIS, descargas globales, servicios de pago ni dependencias ML. Ningún comando Git ni publicación.
- **D007 — Cobertura honesta.** POWER se integrará en Fase 2 y MODIS para una región piloto en Fase 4. La localidad piloto se definirá junto con la disponibilidad y calidad del producto real; no se presupone cobertura satelital ni validación mundial.
- **D008 — Demo local sin autenticación.** Los futuros servicios escucharán localmente. Cualquier exposición pública requiere una evaluación posterior de autenticación, protección de datos, límites y credenciales.

## 2026-11-14 — Fase 1

- **D009 — Compatibilidad comprobada.** Los requisitos publicados de Vite 8.3.8 y plugin React 6.3.0 aceptan Node 22.15.0; se verificó mediante `npm view` y build real. React Leaflet 5 exige React 19 y Leaflet 1.9, instalados conjuntamente. Tailwind usa su plugin de Vite. Se conservaron lockfiles sin actualizar herramientas globales.
- **D010 — Perfil en memoria.** Ubicación y perfil se comparten desde `App`; los cambios confirmados permanecen al navegar y se borran al recargar. No se anticipa la persistencia SQLite ni se confunde un guardado de sesión con almacenamiento duradero. Todos los campos agrícolas son opcionales y el suelo/agua pueden seguir desconocidos.
- **D011 — Separación por fases.** Planificar presenta contexto y ausencia de comparación; no genera secuencias, scores, balances, pronósticos ni datos NASA. El catálogo agronómico y la comparación corresponden a Fase 3.
- **D012 — Cartografía y polos.** Teselas HTTPS OSM, atribución visible y referrer estándar, sin prefetch ni almacenamiento offline propio. Se aceptan coordenadas geográficas hasta ±90°, pero el mapa Mercator solo representa hasta ±85,05112878°; se avisa y no se dibuja un marcador polar desplazado. La selección de mapa normaliza longitud a ±180° y redondea a seis decimales sin prometer esa precisión científica.
- **D013 — Verificación local reproducible.** Playwright inicia FastAPI y Vite en puertos fijos y usa Edge ya instalado, con escritorio y emulación Pixel 7. Se ejecuta axe para WCAG A/AA sobre ambos recorridos y vista técnica. Las simulaciones de fallos de API y teselas se etiquetan en las pruebas; no son fixtures NASA. Primer pase: fallos de contraste; se corrigieron y el pase final fue satisfactorio.
- **D014 — Transporte de pruebas backend.** La versión instalada de Starlette avisó de deprecación del TestClient basado en HTTPX. Las pruebas usan directamente `httpx.ASGITransport` con cliente asíncrono para evitar añadir otra librería o conservar la advertencia; el contrato se verifica además por HTTP real desde Playwright.
- **D015 — Ayudas de desarrollo.** Aplicadas las habilidades Sites (solo local), react-best-practices y verification. No se registró un sitio, no hubo sincronización ni publicación. Los procesos de prueba se cerraron al finalizar.

## 2026-11-14 — Entrega demo con límite de una hora

- **D016 — Alcance de entrega.** La nueva solicitud autoriza continuar por las etapas necesarias para una demo y página del proyecto en una hora. Se conserva la verificación incremental. No se interpreta como autorización de publicación ni Git.
- **D017 — Fuente real y respaldo.** Integrado POWER diario AG/UTC con T2M, T2M_MIN, T2M_MAX y PRECTOTCORR. Se guarda una observación auténtica de Mantaro/enero 2025 con manifest, fecha de descarga, URL y SHA-256 para una demostración reproducible sin conexión NASA. No es un fixture sintético y nunca se aplica silenciosamente a otra ubicación.
- **D018 — Totales incompletos.** La lluvia acumulada solo se muestra si todos los días tienen precipitación válida; con faltantes se devuelve `unavailable`. La media de temperatura usa días válidos y declara calidad parcial cuando corresponda. Se conserva `null` en curvas y tablas.
- **D019 — Caché local.** SQLite almacena resultados normalizados con clave de fuente, parámetros, fechas, ubicación y versión del esquema. TTL siete días; cada payload conserva la versión del producto y fecha de descarga. Sin consultas por movimiento de mapa ni sliders. Por ser una demo pequeña, la clave distingue coordenadas exactas; la deduplicación por celda queda pendiente antes de uso intensivo.

- **D020 — Comparación demostrable y limitada.** El motor `structure-v1` cuenta diversidad, repeticiones y descansos de tres secuencias de tres campañas, sin coeficientes agronómicos inventados. Primera secuencia ilustrativa hasta confirmación del usuario. No hay ranking. La lluvia de escenario se obtiene de una referencia POWER resuelta por el backend, no de cifras del cliente; se mantiene igual para las tres alternativas.
- **D021 — Página del proyecto.** `/` presenta problema, recorridos, ejemplo real, fuentes, método y estado. `/#demo` abre la aplicación; `/#planificar` y `/#monitorear` permiten entrar al recorrido correspondiente. La ilustración SVG es conceptual y no se atribuye a un satélite. No se inventan testimonios, clientes, avales ni afiliación NASA.
- **D022 — Carga de gráficos diferida.** Recharts se carga al abrir Monitorear, separando el panel en un chunk de unos 406 kB y eliminando la advertencia de bundle grande. No se añadió infraestructura externa.
- **D023 — MODIS pendiente por acceso.** Dos intentos REST ORNL DAAC agotaron timeout. Se conserva la demo con un producto NASA y se declara expresamente que el requisito de dos productos sigue pendiente. No se fabrica NDVI ni se marca Fase 4 o auditoría completa como finalizada.
- **D024 — Lanzador local Windows.** Se añaden `DEMO.cmd`, `STOP_DEMO.cmd` y `Start-AgroShift.ps1`. Los servicios se inician ocultos, se registran PID y fecha de creación y se detienen solo si coinciden. Se contempló el Python hijo del redirector de venv verificando relación parental, comando y puerto; se comprobó que la parada deja libres 5173/8000. No se altera la política global de PowerShell.

## Pacha Pulse — perfiles, polígonos y accesibilidad

- **D025 — Marca solicitada.** El usuario renombra el proyecto a Pacha Pulse. Se actualizan marca pública, página, títulos y exportaciones; se conservan identificadores internos estables por compatibilidad. La documentación anterior mantiene el historial AgroShift.
- **D026 — Perfiles sin duplicación.** Cultivador y Agrónomo son modos de presentación sobre el mismo estado y motor. Cultivador usa pasos guiados; Agrónomo expone tabla/método por defecto y procedencia técnica. Ningún modo autoriza inferencias científicas adicionales ni constituye un rol de seguridad.
- **D027 — Delimitación accesible.** Se implementa un polígono activo con vértices por clic/toque, arrastre y alternativa completa de coordenadas/teclado; zoom/escala/encuadre y estados de borrador/confirmado. Geometría, cálculo y persistencia están separados del componente para facilitar la integración UI/UX. Sin rediseño general.
- **D028 — Persistencia explícita.** Solo el contorno se guarda en localStorage versionado; importación/exportación GeoJSON. Área recalculada y validada, sin confiar en el archivo. Cambios en borrador no sustituyen la geometría confirmada; eliminación reversible. La superficie del perfil no se sobrescribe.
- **D029 — Precisión y cobertura.** Turf 7.4 calcula área esférica aproximada. Sin relieve, precisión catastral ni nuevos datos satelitales. Se mantiene consulta NASA por punto representativo, con aviso cuando el punto quede fuera del contorno.
- **D030 — Dos copias distintas.** El usuario confirma Farm_Project como entrega. Project_Farm ocupaba 5173/8000 y causó las primeras pruebas sobre una aplicación distinta. Se preserva esa copia y se usan puertos aislados para comprobar la carpeta correcta. El lanzador identifica raíz/PID/fecha y selecciona un par libre.
